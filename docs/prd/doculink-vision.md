# DOCULINK 

## QUE ES PARA MI 'DOCULINK':
DOCULINK ES UNA APLICACION WEB QUE GESTION EXPEDIENTES PARA CONTACTOS, SIENDO CONTACTOS CUALQUIER ENTIDAD FISICA O JURIDICA. EL OBJETIVO DE DOCULINK ES RESOLVER EL PROBLEMA QUE SE PLANTEA EN EL SEGUIMIENTO DE CASOS O DE GESTIONES A TRAVES DEL UN CENTRO GRAVITACIONAL DE INFORMACION, LLAMADO EXPEDIENTES.
EL PROCESO ES BASTANTE SIMPLE PERO NO CARENTE DE LOGICA DE NEGOCIO, PARTIMOS DE UN CONTACTO QUE PRECISA UNA GESTION CONCRETA, POR EJEMPLO, LA RECLAMACION DE UNA FACTURA O EL SEGUIMIENTO DE LA MISMA HASTA EL COBRO, O LA GESTION DE UN DIVORCIO PARA UN ABOGADO O DESPACHO DE ABOGADOS, O LA GESTION DE UNA OPORTUNIDAD DE VENTA PARA UN COMERCIAL O UN DEPARTAMENTO DE VENTAS, ES DECIR, DOCULINK GESTIONA CASOS PARA CONTACTOS. 
PARA GESTIONAR CADA CASO, SE CREA UN EXPEDIENTE, EL CUAL TENDRÁ LA SUPERVISION DE UN HUB TEAM.

## QUE ES PARA MI UN EXPEDIENTE:
Un expediente es un caso de uso concreto que representa un contenedor del que se derivan iteraciones para resolver un problema o gestionar una actividad para con un contacto y sus intervientes. Por ejemplo, un expediente podría ser la gestión de una reclamación en consumo, la gestión de pago de una factura, el seguimiento de una oportunidad de venta o la resolución de un problema técnico. Cada expediente tiene su propia información, estado y flujo de trabajo. En esencia, el expediente es el espacio donde se centraliza toda la actividad relacionada con un contacto para un caso específico que nos ha demandado realizar, permitiendo una gestión organizada y eficiente de las interacciones y tareas asociadas. Todo expediente tiene un bitacora de eventos (items de tareas), estos eventos son acciones que se realizan sobre el expediente y tienen un timestamp, un tipo, una prioriodad, un estado, una descripcion y elementos asociados (documentos, comunicaciones, evidencias, resoluciones, etc.). El bitacora de eventos registraría las iteraciones que el usuario realiza sobre el expediente, por ejemplo, si el usuario ha enviado la factura por email, en este caso podria registrar este evento en la bitacora con el tipo "hito", la prioridad 3 (normal), la descripción "Enviado factura por email a Mapfre" y como anexo, elemento asociado, el email que se ha enviado con la factura adjunta.
Otro ejemplo, si el usuario ha recibido justificante del pago de una factura, este usuario podría registrar este evento en la bitacora con el tipo "hito", la prioridad 1 (urgente), la descripción "Pago recibido en cuenta bancaria" y como elemento asociado, el justificante del pago, además quiere enviar una notificación al hub team de "Gestión de Cobros" para que estén al tanto de que han realizado el pago pago, ahora que se ha completado el pago y por lo tanto el expediente se ha resuelto, el usuario podría pulsar el boton del expediente "Cerrar expediente" y el sistema le preguntaría si quiere generar un reporte de cierre del expediente, este reporte incluiría un resumen de los eventos registrados en la bitacora, los documentos asociados, las comunicaciones realizadas, y cualquier otra información relevante para el expediente, este reporte se podría generar en formato PDF y se podría enviar por email al contacto y a los integrantes del hub team que han participado en la gestión del expediente.


## QUE ES PARA MI UN HUB TEAM:
Un hub team es un equipo de trabajo especializado en un área concreta (por ejemplo, soporte, ventas, administración, gestión de cobros, etc.) que es participe del expediente donde se le ha incorporado. Esta compuesto por un responsable, el cual es el que coordina al equipo, lo mantiene y define sus integrantes. Estos integrantes son los usuarios de la aplicación y según el orden en que aparecen en la tabla de hub team members, tienen la jerarquia establecida.  El responsable del hub team, con el rol minimo de 'admin', define a los integrantes dentro del hub y especifica su jerarquia y si estan o no esta activos.

##  QUE ES PARA MI UN CONTACTO:
Un contacto es una persona o entidad con la que se interactúa a través de los expedientes. El contacto es el sujeto central de cada expediente, ya que representa al cliente, o parte interesada para la cual se está gestionando el caso específico. Cada contacto tiene su propia información de perfil (nombre, datos de contacto, historial de interacciones, etc.) y puede estar asociado a múltiples expedientes a lo largo del tiempo. La gestión de los contactos es fundamental para asegurar una comunicación efectiva y personalizada, así como para mantener un registro organizado de todas las interacciones y actividades relacionadas con cada caso específico que se maneja en los expedientes.

## QUE ES PARA MI LA BITACORA DE EVENTOS:
La bitácora de eventos es un registro cronológico y detallado de todas las acciones,interacciones y cambios de estado que ocurren dentro de un expediente. Cuando el usuario realiza una acción relevante, como enviar la factura para que nos pagen, via  email (acción que realiza externamente a la aplicación), el usuario registra esa acción en la bitácora de eventos del expediente correspondiente, proporcionando una descripción de la acción realizada, el tipo de evento, la prioridad (del 1 al 3), el estado (pendiente, en progreso, completado) y los elementos que pueden estar asociados, como anexo, (como documentos adjuntos o comunicaciones relacionadas). La bitácora de eventos es esencial para mantener un historial completo y transparente de la gestión del expediente, permitiendo a los colaboradores (hub team y usuarios) involucrados, tener una visión clara de todas las actividades realizadas y pendientes, facilitando la coordinación y seguimiento efectivo del caso específico que se está gestionando.
De esta forma, la bitácora de eventos no solo sirve como un registro histórico, sino también como una herramienta de gestión activa que ayuda a los usuarios a mantenerse organizados, priorizar tareas y asegurar que todas las acciones necesarias para resolver el expediente se realicen de manera oportuna y eficiente.

## QUE ES PARA MI EL TEMPLATE DE ACCIONES REUTILIZABLES PARA EL BITACORA:
El template de acciones reutilizables para la bitácora es una funcionalidad que permite a los usuarios crear y guardar plantillas predefinidas de eventos o acciones comunes que se registran en la bitácora de eventos de los expedientes. Dado que ciertos tipos de eventos o acciones tienden a repetirse con frecuencia (por ejemplo, "envío de factura", "revisión de contrato", "seguimiento de pago"), el template de acciones reutilizables permite a los usuarios definir estos eventos una sola vez, especificando su tipo, prioridad, estado y cualquier elemento asociado, para luego poder seleccionarlos fácilmente al registrar un nuevo evento en la bitácora. Esto no solo ahorra tiempo al evitar tener que ingresar manualmente la misma información cada vez, sino que también asegura consistencia en la forma en que se registran los eventos, facilitando la organización y el seguimiento efectivo de las actividades dentro de cada expediente.

## QUE ES PARA MI EL SISTEMA DE COMUNICACIONES (NOTIFICACIONES) DEL EXPEDIENTE:
El sistema de comunicaciones del expediente es una funcionalidad que permite gestionar y centralizar todas las interacciones y notificaciones relacionadas con un expediente específico. Este sistema se encarga de enviar notificaciones automáticas a los colaboradores del expediente.
Para tener una idea de como es mi visión de esta caracteristica, pongamos por ejemplo, que un usuario ha creado un expediente para el seguimiento de una factura, y en la cabecera ha puesto como 'colaboradores' a un hub team de 'Gestión de Cobros' y al usuario 'Miguel Cabrera' (owner). En este punto, solo estos dos grupos pueden ser involucrados en el bitacara de eventos, es decir, solo el usuario 'Miguel Cabrera' y los integrantes del hub team 'Gestión de Cobros', incluido el responsable, pueden ser involucrados en los eventos de la bitácora y por consiguiente solo estos recibirán notificaciones.
Ahor que ya tiene el expediente creado y en proceso, el usuario registra un evento en la bitacora diciendo "Enviada la factura por email para su pago" y entiende que debe notificar de este acto al hub team de 'Gestión de Cobros' y no a "Miguel Cabrera" que es el Director de la Empresa y esto no le interasa. Al seleccionar al hub team, los integrantes de este recibirán una notificación de tipo 'info' con el mensaje que el usuario ha creado para tal fin, "Enviada factura y a la espera del pago, cuando se reciba lo notificaré". 
Pasado unos días el usuario ha recibido el pago de la factura, y registra un nuevo evento en la bitácora diciendo "Pago recibido, pendiente de confirmación en cuenta bancaria" y entiende que el hub "Gestión de Cobros" debe ser notificado, pero esta vez necesita recibir una respuesta a esta notificación, ya que el pago tiene que confirmarlo el hub team "Gestión de Cobros". El usuario elige al hub "Gestión de Cobros", elige el tipo de notificación "actionable" y escribe el mensaje "Pago recibido, pendiente de confirmación en cuenta bancaria, por favor confirmar cuando lo tengáis". En este caso, los integrantes del hub team "Gestión de Cobros" recibirán una notificación de tipo "actionable" con el mensaje que el usuario ha creado, y tendrán la opción de responder a esta notificación con un mensaje de texto diciendo "Pago confirmado en cuenta bancaria", al responder a esta notificación, el usuario que ha registrado el evento en la bitácora recibirá una nueva notificación de tipo 'success' con el mensaje que el integrante del hub team "Gestión de Cobros" ha escrito como respuesta a la notificación original.
Este sistema de comunicaciones del expediente es esencial para mantener a todos los colaboradores involucrados en el expediente informados y coordinados, asegurando que todas las acciones relevantes se comuniquen de manera efectiva y oportuna.

## QUE ES PARA MI LA GESTION DE USUARIOS Y ROLES:
La gestión de usuarios y roles es una funcionalidad que permite administrar el acceso y los permisos de los diferentes usuarios dentro de la aplicación. Dado que los hub teams pueden estar compuestos por múltiples integrantes con diferentes responsabilidades y niveles de acceso, la gestión de usuarios y roles permite definir quién puede acceder a qué expedientes, qué acciones pueden realizar, y qué información pueden visualizar. Por ejemplo, el responsable del hub team puede tener permisos para crear y asignar expedientes, mientras que un integrante del equipo puede tener permisos limitados para solo visualizar ciertos expedientes o registrar eventos en la bitácora. Esta funcionalidad es crucial para garantizar la seguridad, privacidad y organización dentro de la aplicación, asegurando que cada usuario tenga acceso solo a la información y funcionalidades que son relevantes para su rol dentro del equipo y la gestión de los expedientes.

## QUE ES PARA MI LA INTEGRACIÓN DE LA IA EN VARIOS PUNTOS DEL FLUJO:
La integración de la IA en varios puntos del flujo de gestión de expedientes es una funcionalidad que permite aprovechar las capacidades de inteligencia artificial para mejorar la eficiencia, precisión y personalización en la gestión de los casos. Por ejemplo, la IA puede ser utilizada para analizar automáticamente los documentos asociados a un expediente y extraer información relevante, generar resúmenes de la bitácora de eventos, sugerir acciones a tomar basándose en patrones históricos, o incluso predecir posibles resultados o riesgos asociados a un caso específico. Esta integración no solo agiliza el proceso de gestión, sino que también proporciona insights valiosos que pueden ayudar a los hub teams a tomar decisiones más informadas y a ofrecer un servicio más personalizado y efectivo a los contactos involucrados en cada expediente.
Otro caso de uso importante de la IA, es la generación automática de eventos en la bitácora a partir de interacciones externas. Por ejemplo, si un usuario envía una factura por email, la IA podría detectar ese envío (a través de una integración con el sistema de correo) y generar automáticamente un evento en la bitácora del expediente correspondiente, registrando la acción sin que el usuario tenga que hacerlo manualmente. Esto no solo ahorra tiempo, sino que también asegura que todas las acciones relevantes se registren de manera oportuna y precisa, mejorando la trazabilidad y gestión de los expedientes.

## QUE ES PARA MI EL PROCESO DE FACTURACIÓN:
El proceso de facturación es una funcionalidad que permite gestionar todo lo relacionado con la generación, seguimiento y cobro de facturas dentro de la aplicación. Dado que muchos expedientes pueden estar relacionados con actividades comerciales o de servicios que requieren la emisión de facturas, esta funcionalidad facilita lacreación de facturas, su asociación a los expedientes correspondientes, el seguimiento de su estado (emitida, enviada, pagada, vencida), y la gestión de rec      cv 


    ordatorios o acciones relacionadas con el cobro. Además, el proceso de facturación puede incluir integraciones con sistemas externos de facturación o contabilidad, así como funcionalidades para generar reportes y análisis relacionados con las facturas emitidas y su impacto en la gestión de los expedientes. En esencia, el proceso de facturación es una parte integral de la aplicación que contribuye a una gestión más completa y eficiente de los casos específicos que involucran actividades comerciales o de servicios, asegurando que la parte financiera de la gestión de los expedientes también esté bien organizada y controlada.

## QUE ES PARA MI LA API REST PARA INTEGRACIÓN CON SISTEMAS EXTERNOS:
La API REST para integración con sistemas externos es una funcionalidad que permite a la aplicación comunicarse e intercambiar datos con otras aplicaciones o sistemas de manera segura y eficiente. Dado que los expedientes gestionados en la aplicación pueden requerir información o acciones que involucran sistemas externos (por ejemplo, un sistema de CRM, un software de contabilidad, una plataforma de correo electrónico, etc.), la API REST proporciona un conjunto de endpoints que permiten a estos sistemas externos acceder a la información de los expedientes, crear o actualizar eventos en la bitácora, gestionar documentos, o realizar cualquier otra acción relevante. Esta integración es crucial para asegurar que la aplicación pueda funcionar de manera fluida dentro del ecosistema tecnológico de la organización, permitiendo una gestión más completa y eficiente de los expedientes al aprovechar las capacidades de otros sistemas y herramientas que ya estén en uso.

## PARA QUIEN ES DOCULINK:

## QUE ES PARA EL GESTOR DE DOCUMENTOS:
El gestor de documentos es una funcionalidad dentro de la aplicación que permite asociar, organizar y gestionar documentos relacionados en los expediente y que tienen una consideración especial. 
El expediente puede incorporar, anexionar,  dos tipos de documentos, documentos de caracter probatorios, de evidencias, por ejemplo un email, una captura de pantalla, un justificante de pago y que tiene la misión de aportar información relevante para la gestión del expediente, y por otro lado, documentos que tienen que ser firmados por las partes involucradas, como contratos, acuerdos, autorizaciones, etc. o que simplemente son documentos asociados a cada expediente, como facturas, comunicaciones, informes, etc. y tienen una función esencial para asegurar que toda la información relevante esté centralizada y fácilmente accesible para los hub teams y los contactos involucrados en cada caso específico.

Para estos ultimos casos, la aplicación cuenta con un móduclo específico y dedicado en exlusiva, el gestor de documentos, donde además de gestionar este tipo de documentos, se realiza el control de firmas.
